## 🗺️ [한눈에 보는 학습 로드맵] 비전공자 0베이스 이론 개념 정립 25선 리스트

공부하실 때 아래 **Lv.1(완전 기초)부터 Lv.7(실무 운영·철거)까지 총 25개 개념**을 위에서 아래로 하나씩 읽으며 체크(`[v]`)해 보세요. 앞 단계 개념이 뒤 단계의 디딤돌이 되도록 순서대로 배열되어 있습니다.

### 🟢 Lv.1 인터넷과 컴퓨터가 대화하는 가장 기초 원리 (네트워크 5대 기초)
- [ ] **개념 01. 클라이언트(Client)와 서버(Server):** 손님(내 스마트폰/브라우저)이 주문(요청, `Request`)하면, 주방(AWS 컴퓨터)이 요리(웹페이지 응답, `Response`)를 내어주는 관계
- [ ] **개념 02. IP 주소 (공인 IP vs 사설 IP):** 전 세계 우편배달부가 찾아오는 **도로명 주소(공인/퍼블릭 IP: `43.201.142.88`)** vs 우리 건물 안에서만 부르는 **내선 번호(사설/프라이빗 IP: `10.0.1.24`)**
- [ ] **개념 03. CIDR 표기법 (`/16`, `/24`, `/32`, `0.0.0.0/0`):** 땅의 크기를 나타내는 숫자. `/16`은 큰 단지(65,536개), `/24`는 작은 구역(256개), **`/32`는 딱 1대의 컴퓨터**, **`0.0.0.0/0`은 전 세계 모든 인터넷 주소**
- [ ] **개념 04. 포트 번호 (Port: `80`, `443`, `22`):** 건물 주소(IP)까지 찾아온 뒤 들어가는 **출입문 번호**. `80`은 일반 손님 정문(HTTP), `443`은 암호화 보안 정문(HTTPS), **`22`는 관리자 전용 뒷문(SSH)**
- [ ] **개념 05. HTTP 상태 코드 (`200 OK`)와 `curl`:** 손님이 문을 두드렸을 때 서버가 **"정상입니다!"라고 답하는 숫자 암호가 `200 OK`** 이며, 브라우저 없이 글자만으로 이 응답을 확인하는 도구가 `curl`

### 🔵 Lv.2 AWS 클라우드에 내 땅과 도로 건설하기 (VPC 네트워크 4총사)
- [ ] **개념 06. 리전(Region: `ap-northeast-2`)과 가용 영역(AZ):** 아마존이 전 세계에 지어둔 데이터센터 도시 중 **서울 지점(`ap-northeast-2`)** 과 그 안의 독립된 건물 단지(`2a`, `2c`)
- [ ] **개념 07. VPC (`10.0.0.0/16`):** AWS 서울 땅에 남들이 못 들어오게 울타리를 친 **나만의 전용 신도시 부지**
- [ ] **개념 08. 서브넷 (Public Subnet vs Private Subnet):** 신도시 땅을 쪼갠 구역. 외부 손님이 오는 **1층 대로변 상가 구역(`Public Subnet`)** 과 외부와 차단된 **지하 금고 구역(`Private Subnet`, DB 보관용)**
- [ ] **개념 09. 인터넷 게이트웨이 (`IGW`):** 울타리로 막힌 신도시(`VPC`)와 바깥 인터넷 고속도로를 연결해 주는 **유일한 정문 톨게이트** (공인 IP와 사설 IP를 1:1로 자동 변환)
- [ ] **개념 10. 라우팅 테이블 (`Route Table`)과 서브넷 연결 (`Associate`):** 갈림길 이정표. **"바깥 세상(`0.0.0.0/0`)으로 갈 때는 정문(`IGW`)으로 가라"**고 적어두고, 이를 상가 구역(`Public Subnet`)에 **명시적으로 부착(`Associate`)** 해야 길이 뚫림

### 🛡️ Lv.3 해커를 막는 2중 방화벽과 작업자 신분증 (보안 5대 핵심)
- [ ] **개념 11. 보안 그룹 (`Security Group`)과 최소 허용 원칙:** 매장 건물(`EC2`) 문 앞을 지키는 **2차 전담 경호원**. `80`번 문은 손님용으로 전체(`0.0.0.0/0`) 개방하되, `22`번 관리자 문은 **내 공인 IP(`/32`)만 허용**하고 `0-65535` 전체 개방은 절대 금지!
- [ ] **개념 12. NACL (`Stateless`) vs 보안 그룹 (`Stateful`):** 상가 입구 1차 차단기(`NACL`)는 기억력이 없어 들어올 때·나갈 때 모두 검사하지만, 매장 앞 2차 경호원(`Security Group`)은 **한 번 들어온 손님 얼굴을 기억해 나갈 때(Outbound)는 자동 통과(`Stateful`)** 시킴
- [ ] **개념 13. SSH 키페어 (`.pem`)와 동적 IP 대안 (`SSM`):** 관리자 뒷문(`22`번)을 여는 **암호 열쇠 파일(`.pem`, 권한 `400`)**. 카페 등 내 IP가 자주 바뀔 때는 22번 문을 아예 안 열고도 접속하는 **`AWS SSM Session Manager`** 가 가장 안전함
- [ ] **개념 14. IAM 최소 권한 원칙 ([least-privilege-policy.json](../iam/least-privilege-policy.json)):** 매장 경호원(보안 그룹)과 달리, **"누가 AWS에서 공사를 할 수 있는가"**를 정하는 **공사장 사원증**. 만능키(`AdministratorAccess`) 대신 서울 리전(`ap-northeast-2`)의 필수 작업만 허용하고 타 서비스(`S3`, `RDS`)는 명시적 차단(`Deny`)
- [ ] **개념 15. 감사 로그 (`CloudTrail`)와 임시 권한 (`STS AssumeRole`):** "누가·언제 보안 그룹을 바꿨는지" 다 기록하는 **CCTV 장부(`CloudTrail`)** 와, 필요할 때만 1시간짜리 임시 출입증을 빌려 쓰는 **`AssumeRole`(JIT)**

### 🖥️ Lv.4 임대 컴퓨터에 웹 서버와 도커 컨테이너 띄우기 (컴퓨팅 & 배포 3대 핵심)
- [ ] **개념 16. EC2 인스턴스 (`t3.micro`):** 상가 구역 안에 세운 **24시간 켜져 있는 임대 컴퓨터(가게 건물)**
- [ ] **개념 17. 웹 서버 `Nginx` ([nginx/default.conf](../nginx/default.conf)):** 가게 1층 80번 문 뒤에서 일반 손님(`/`)에게는 홈페이지([web/index.html](../web/index.html))를 주고, 점검원(`/health`)에게는 0.001초 만에 `"OK"`를 돌려주는 **안내 데스크 직원**
- [ ] **개념 18. 도커 컨테이너 (`Docker`, [Dockerfile](../Dockerfile))와 포트 포워딩 (`-p 80:80`):** 어떤 컴퓨터에 가도 1초 만에 똑같은 매장을 차릴 수 있게 포장한 **밀키트 상자**. 건물 80번 문과 상자 80번 문을 파이프로 연결하는 것이 **`-p 80:80`**

### 🔍 Lv.5 외부 접속 이중 검증과 3초 에러 진단법 (검증 & 트러블슈팅 3대 핵심)
- [ ] **개념 19. 외부 접속 검증 방식 (A) 브라우저 vs (B) `GET /health`:** 눈으로 디자인을 확인하는 **방식 A(`http://43.201.142.88`)** 와, 기계(로드밸런서·모니터링 봇)가 1초 만에 서버 생존 여부를 확인하는 **방식 B(`/health` → `200 OK` `"OK"`)**
- [ ] **개념 20. `Operation timed out` (`exit 28`) vs `Connection refused` (`exit 7`):**
  - **`Timed out` (전화 신호조차 안 감):** 길(`Route Table`)이 끊겼거나 경호원(`Security Group`)이 막고 있음!
  - **`Refused` (문 앞까지 갔는데 문이 잠김):** 길과 경호원은 통과했으나 EC2 안에서 `Nginx`/`Docker` 프로그램이 꺼져 있음!
- [ ] **개념 21. 공개 로그 민감정보 마스킹 (Masking):** GitHub 같은 공개 장소에 에러 로그를 올릴 때 계좌번호 격인 **12자리 Account ID(`********9012`), Access Key, 보안 토큰을 별표(`*`)로 가리는 보안 수칙**

### 📈 Lv.6 손님이 폭주할 때 매장을 자동으로 늘리는 기술 (확장성 2대 핵심)
- [ ] **개념 22. 서버 병목(Bottleneck) 진단과 `ALB` (로드밸런서):** 손님이 몰려 CPU가 `80%` 이상 치솟을 때, 매장 입구에서 손님을 여러 매장(`EC2`)으로 골고루 분산해 주는 **총괄 지배인(`ALB`)** 과 **보안 그룹 체이닝(`ALB-SG -> EC2-SG`)**
- [ ] **개념 23. 오토 스케일링 (`Auto Scaling Group`):** 평균 **`CPU > 70%`가 5분 지속되면 매장(`EC2`)을 자동으로 `+1대` 늘리고(Scale-Out)**, 한가해지면(`CPU < 30%` 15분) 다시 줄여(`Scale-In`) 요금을 아끼는 자동 고무줄 시스템

### 🧹 Lv.7 요금 폭탄을 막는 역순 철거와 태그 관리 (운영 & 비용 2대 핵심)
- [ ] **개념 24. 표준 태그(`Name/Project/Owner/Env/CostCenter`):** 클라우드에 만든 모든 시설물에 **"누가·무슨 프로젝트로 만들었는지" 이름표를 붙여** 주인 없는 유령 리소스 과금을 막는 규칙
- [ ] **개념 25. 의존성 역순 철거 ([docs/cleanup-checklist.md](./cleanup-checklist.md)):** 안쪽 건물(`EC2 Terminate` → `EIP/EBS`)부터 허물고 바깥 울타리(`IGW` → `Subnet/RT/SG` → `VPC`)를 지워야 `DependencyViolation` 에러가 안 나며, 철거 후 **`$0.00`** 을 반드시 확인!

## 🐣 0단계. 도대체 왜 ‘클라우드(AWS)’에 올려야 하나요?

내가 내 노트북에서 멋진 홈페이지([web/index.html](../web/index.html))를 만들었다고 해볼게요.
- 내 노트북에서만 켜두면 **내 방 공유기 안(`localhost`)** 에서만 보이고, 친구가 스마트폰으로 접속하려고 하면 못 들어옵니다.
- 게다가 내가 밤에 노트북을 덮고 자면 홈페이지도 같이 꺼져버립니다.
- 그래서 **아마존(AWS)이 서울(`ap-northeast-2`) 데이터센터에 24시간 내내 켜둔 컴퓨터와 도로망을 빌려서(임대해서)** 내 홈페이지를 올려두는 것, 이것이 바로 **클라우드 배포**입니다!

## 🏗️ 1단계. 땅을 빌리고 도로를 까는 4총사 (`VPC` · `Subnet` · `IGW` · `Route Table`)

클라우드에 무턱대고 컴퓨터(`EC2`)부터 덜컥 놓으면 해커들이 사방에서 들어옵니다. 그래서 **울타리와 도로**부터 설계해야 합니다.

| 클라우드 용어 | 우리 미션 설정값 | 🏘️ 실생활 비유 (신도시 상가 단지) | 하는 일 (한 줄 요약) |
| :---: | :---: | :--- | :--- |
| **1. VPC**<br>(Virtual Private Cloud) | `codyssey-vpc`<br>(`10.0.0.0/16`) | **나만의 전용 아파트·상가 단지 울타리** | AWS라는 거대한 땅 위에 남들이 못 들어오게 높은 담장을 친 **나만의 독립된 네트워크 공간**입니다. |
| **2. Public Subnet**<br>(퍼블릭 서브넷) | `codyssey-public-subnet`<br>(`10.0.1.0/24`) | **단지 내 ‘1층 외부 손님용 상가 구역’** | 단지(`VPC`)라는 큰 땅을 쪼개서 **외부 손님이 찾아올 수 있게 지정한 구역**입니다. *(반대로 DB처럼 숨겨야 하는 건 ‘지하 금고 구역’인 **Private Subnet**에 둡니다.)* |
| **3. Internet Gateway**<br>(인터넷 게이트웨이, `IGW`) | `codyssey-igw`<br>(`igw-0a1b...`) | **단지 정문 톨게이트** | 담장(`VPC`)으로 둘러싸인 단지와 바깥 세상(**인터넷 고속도로**)을 연결해 주는 **유일한 출입 정문**입니다. |
| **4. Route Table**<br>(라우팅 테이블) | `codyssey-public-rt`<br>(`0.0.0.0/0 -> IGW`) | **단지 안 갈림길에 세워진 ‘이정표’** | 상가 구역(`Subnet`) 안에서 패킷이 길 잃지 않게 **“단지 안끼리는 내부 도로(`local`)로 가고, 바깥 세상(`0.0.0.0/0`)으로 나갈 땐 정문(`IGW`)으로 가라!”** 고 알려주는 표지판입니다. |

### 🔢 [왕초보 필수!] IP 주소 뒤의 슬래시(`/16`, `/24`, `/32`, `0.0.0.0/0`) 숫자는 무슨 뜻인가요?
IP 주소(예: `10.0.1.24`)는 점(`.`)으로 나뉜 4칸짜리 주소입니다. 뒤에 붙는 `/숫자`는 **“앞에서부터 어디까지가 우리 구역 이름인지”** 를 뜻합니다.
1. **`10.0.0.0/16` (큰 단지 `VPC`):** 앞의 두 칸(`10.0.`)만 고정! 뒤의 두 칸을 마음대로 쓸 수 있어서 약 **65,536개**의 방 번호를 가진 큰 단지입니다.
2. **`10.0.1.0/24` (작은 구역 `Subnet`):** 앞의 세 칸(`10.0.1.`)까지 고정! 마지막 한 칸(`0~255`)만 바꿀 수 있어서 약 **256개**의 방 번호를 가진 1층 구역입니다.
3. **`211.234.118.42/32` (내 컴퓨터 딱 1대!):** 네 칸 전체(`32비트`)가 100% 똑같아야 함! 즉 **“오직 내 컴퓨터 딱 1대만 허용한다”** 는 뜻입니다. (보안 그룹 `SSH 22`번 문에 사용!)
4. **`0.0.0.0/0` (전 세계 모든 인터넷!):** 고정된 칸이 `0`개! 즉 **“국적·주소 불문하고 전 세계 모든 IP 주소를 다 의미한다”** 는 뜻입니다. (웹 `80`번 문과 라우팅 테이블 인터넷 경로에 사용!)

## 🛡️ 2단계. 문지기와 사원증 구분하기 (`NACL` vs `Security Group` vs `IAM`)

평가자님이 가장 좋아하는 질문이 바로 **“보안 그룹(Security Group)과 IAM은 둘 다 보안인데 뭐가 달라요?”**, 그리고 **“NACL과 보안 그룹은 뭐가 달라요?”** 입니다.

### (1) `IAM` vs `Security Group` — 사원증 vs 매장 경호원
- **🔐 IAM (Identity & Access Management) = ‘공사장 소장님 사원증’**
  - **역할:** **“누가 AWS에 로그인해서 건물을 짓고(`CreateVpc`, `RunInstances`) 부술 수 있는가?”** 를 통제합니다.
  - **최소권한 원칙:** 신입 직원에게 건물 전체를 폭파할 수 있는 마스터키(`AdministratorAccess`)를 주면 큰일 나겠죠? 그래서 우리가 만든 [`iam/least-privilege-policy.json`](../iam/least-privilege-policy.json) 카드키에는 **“오직 서울 지점(`ap-northeast-2`)에서 이번 실습에 필요한 네트워크와 서버만 만들 수 있고, 금고실(`S3`, `RDS`)은 절대 못 건드린다”** 라고 적혀 있습니다.
- **🛡️ Security Group (보안 그룹) = ‘내 매장(EC2) 문 앞 전담 경호원’**
  - **역할:** 이미 지어진 매장 건물(`EC2`) 앞에서 **“어떤 손님(IP)이 몇 번 출입문(포트)으로 들어올 수 있는가?”** 를 검사하는 **가상 방화벽**입니다.

### (2) `Network ACL (NACL)` vs `Security Group` — 1차 구역 차단기 vs 2차 매장 경호원
우리 아키텍처 다이어그램([`docs/architecture.png`](./architecture.png))을 보면 초록색 인바운드 화살표와 하늘색 아웃바운드 화살표가 두 개의 방화벽을 통과합니다.
1. **1차 방화벽 `Network ACL (NACL)` = 상가 구역(`Subnet`) 입구의 ‘무인 차단기’ (`Stateless` 비상태 검사):**
   - 기억력이 없어서 손님이 **들어올 때(Inbound)도 검사하고, 볼일 보고 나갈 때(Outbound)도 처음 보는 사람처럼 또 검사**합니다.
2. **2차 방화벽 `Security Group (보안 그룹)` = 매장(`EC2`) 문 앞의 ‘기억력 좋은 경호원’ (`Stateful` 상태 저장 검사):**
   - 손님이 들어올 때(Inbound 80번 문) 한 번 허락해 주면 출입 장부에 얼굴을 기억해 둡니다. 그래서 손님이 **응답을 들고 나갈 때(Outbound)는 따로 검사하지 않고 자동으로 문을 열어줍니다!**

## 🖥️ 3단계. 건물(`EC2`)을 세우고 출입문(`포트`)과 안내원(`Nginx`/`Docker`) 배치하기

이제 1층 상가 구역(`Public Subnet`) 안에 드디어 내 컴퓨터 건물인 **`EC2 인스턴스`(`t3.micro`)** 를 세웠습니다!

### (1) 두 개의 주소: `퍼블릭 IP` vs `사설(프라이빗) IP`
- **퍼블릭 IP (`43.201.142.88`):** 택배 기사님이나 외부 손님이 인터넷 네비게이션에 찍고 찾아오는 **‘도로명 주소(공인 IP)’** 입니다.
- **프라이빗 IP (`10.0.1.24`):** 우리 아파트 단지(`VPC 10.0.0.0/16`) 안에서 이웃끼리만 부르는 **‘101동 101호(내부 주소)’** 입니다.
- **Internet Gateway(`IGW`)의 마법:** 외부 손님이 `43.201.142.88`로 찾아오면 정문(`IGW`)이 `10.0.1.24`로 자연스럽게 연결(1:1 NAT)해 줍니다!

### (2) 세 개의 출입문 번호 (`포트 Port`)
같은 매장 건물(`43.201.142.88`)이라도 용도에 따라 출입문 번호가 다릅니다.
- **`80`번 문 (`HTTP`):** 일반 손님들이 홈페이지 구경하러 들어오는 **1층 정문** → 누구나 들어와야 하므로 보안 그룹에서 **`0.0.0.0/0` (전체 허용)** 으로 엽니다.
- **`443`번 문 (`HTTPS`):** 암호화 자물쇠가 걸린 **보안 정문** (보너스 과제 1 `Let's Encrypt` 적용 시 사용).
- **`22`번 문 (`SSH`):** 사장님(나)이 매장 안 주방으로 원격 접속해 요리법(코드)을 고치는 **직원 전용 뒷문** → 해커가 못 들어오게 보안 그룹에서 **오직 내 공인 IP(`211.234.118.42/32`)에게만** 열어둡니다!
- **금지 규칙 (`0-65535` 전체 개방 금지):** 건물 벽 전체를 허물어 모든 문을 다 열어두는 행동이므로 절대 금지합니다.

### (3) 매장 안의 안내 데스크 직원 (`Nginx`)과 프랜차이즈 박스 (`Docker`)
- **`Nginx` ([`nginx/default.conf`](../nginx/default.conf)):** 80번 정문 바로 뒤에서 손님을 맞이하는 직원입니다.
  - 손님이 그냥 정문(`/`)으로 들어오면 → 멋진 홈페이지 화면([`web/index.html`](../web/index.html))을 보여줍니다 (**방식 A**).
  - 점검원이 `/health` 창구로 물어보면 → 0.001초 만에 **`200 OK`와 `"OK"`** 글자를 돌려줍니다 (**방식 B**).
- **`Docker` ([`Dockerfile`](../Dockerfile)):** 이 직원(`Nginx`)과 설정표, 홈페이지를 **하나의 규격화된 컨테이너 박스(`codyssey-web:latest`)** 로 포장한 것입니다. `-p 80:80` 옵션으로 건물 80번 문과 박스 80번 문을 연결해 영업합니다 (**보너스 과제 2**).

## 🔄 4단계. 한눈에 따라가는 ‘손님(패킷)의 6단계 왕복 여행’

친구가 스마트폰 브라우저 주소창에 **`http://43.201.142.88`** 을 치고 엔터를 누르면 어떤 일이 벌어질까요?

1. **[출발]** 친구 스마트폰에서 출발한 요청이 인터넷 고속도로를 타고 우리 서울 리전 **단지 정문(`Internet Gateway`)** 에 도착합니다.
2. **[주소 변환]** 정문(`IGW`)이 도로명 주소(`43.201.142.88`)를 단지 내부 호수(`10.0.1.24`)로 바꿔서 안으로 들여보냅니다.
3. **[이정표 확인]** **라우팅 테이블(`Route Table`)** 이정표를 보니 `10.0.0.0/16`은 단지 내부(`local`) 길이라고 적혀 있어 **1층 상가 구역(`Public Subnet`)** 으로 안내합니다.
4. **[1차 검문]** 상가 구역 입구의 **`Network ACL`** 이 “80번 문 손님이군, 통과!” 하고 들여보냅니다.
5. **[2차 검문]** 매장 문 앞의 **`Security Group`** 경호원이 출입 명부를 보고 “80번 문은 `0.0.0.0/0`(누구나 허용)이네, 통과!” 하고 들여보냅니다.
6. **[응답 완료]** 매장 안 **`EC2`** 에서 대기하던 **`Nginx`/`Docker`** 직원이 반갑게 **`200 OK` (`Hello Cloud!` 홈페이지)** 를 들려 보내면, 왔던 길을 거꾸로 타고 친구 스마트폰 화면에 짠! 하고 나타납니다.

## 📈 6단계. 손님이 대박 났을 때(`ALB`)와 가게를 안전하게 접을 때(`Cleanup`)

### (1) 손님이 너무 많이 몰릴 때 — 확장성 & `ALB` ([`docs/scalability-and-alb-guide.md`](./scalability-and-alb-guide.md))
- 처음엔 `t3.micro` 작은 매장 1개로 시작했지만, 손님이 몰려 CPU가 `80%` 넘게 치솟으면 매장이 느려집니다(**병목 현상**).
- 이때 매장 입구에 **총괄 지배인(`ALB, Application Load Balancer`)** 을 세우고, 뒤에 똑같은 매장(`EC2`)을 2개~4개(**`Auto Scaling`: CPU 70% 넘으면 자동 증설**)로 늘립니다.
- 지배인(`ALB`)은 15초마다 각 매장에 **`GET /health`** 전화를 걸어 **`"OK"`** 라고 답하는 건강한 매장으로만 손님을 골고루 나눠 보냅니다!

### (2) 실습이 끝나고 가게를 철거할 때 — 과금 방지 역순 정리 ([`docs/cleanup-checklist.md`](./cleanup-checklist.md))
- 클라우드에서 가장 무서운 것은 **“실습 끝났는데 안 지워서 다음 달에 카드 요금 나가는 것”** 입니다.
- 특히 컴퓨터(`EC2`)를 **중지(`Stop`)** 만 해두면 하드디스크(`EBS`)와 고정 주소(`Elastic IP`) 보관료가 계속 나갑니다. 반드시 **종료(`Terminate`, 완전 반납)** 해야 합니다.
- 철거할 때는 **안쪽 건물부터 바깥 울타리 순서(역순)** 로 지워야 에러(`DependencyViolation`)가 안 납니다:  
  👉 **① `EC2` 종료 → ② `Elastic IP` 해제 & `EBS` 삭제 → ③ 정문(`IGW`) 떼어내고 삭제 → ④ 구역(`Subnet`)·이정표(`RT`)·경호원(`SG`) 삭제 → ⑤ 담장(`VPC`) 최종 삭제 → ⑥ 요금표(`Billing`) `$0.00` 확인!**
